# Практична робота №8
## Варіант 6 — Кулінарна книга

## 1. SQL-ін'єкція

Перевірявся пошук за інгредієнтом.

Payload:

`' OR '1'='1`

SQL-запити використовують PDO prepared statements.
Значення користувача передається через параметри, а не
конкатенується із SQL.

Результат: SQL-ін'єкцію не виявлено.

## 2. XSS

Payload:

`<script>alert(1)</script>`

Payload було введено в поле інгредієнтів та збережено.

До виправлення:
дані, вставлені через innerHTML без екранування, могли
інтерпретуватися браузером як HTML.

Після виправлення:
користувацькі дані екрануються перед вставленням у HTML
або виводяться через textContent.

Результат:
JavaScript не виконується, payload відображається як текст.

## 3. CSRF

Додавання, редагування та видалення рецептів захищено
CSRF-токеном, який зберігається в PHP-сесії.

Запит без токена:

HTTP 403

Запит з неправильним токеном:

HTTP 403

Запит з правильним токеном:

операція виконується успішно.

## 4. Серверна валідація

Перевірено:
- порожню назву;
- порожні інгредієнти;
- cook_time_min = 0;
- cook_time_min < 0;
- некоректний id.

Некоректні дані повертають HTTP 400 та не записуються в БД.

## 5. Видалення

Видалення рецепта виконується лише POST-запитом.

Перед видаленням користувач отримує confirm(),
а сервер додатково перевіряє CSRF-токен.

GET-запит не може видалити рецепт.

## 6. Обробка помилок

Внутрішні PDO/PHP помилки записуються через error_log().

Клієнту повертається лише загальне повідомлення:

`Внутрішня помилка сервера.`
